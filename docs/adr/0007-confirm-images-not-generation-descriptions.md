# Confirm the generated image and Client preferences, not a pre-render description

The novice evaluation found a rendered sidebar in a concept whose generated
description promised upper navigation. Copying that pre-render description into
style confirmation silently agreed two different directions.

New concept selection cards therefore show images and identifying names, with
ordinary-language keep/avoid prompts. New confirmation summaries contain the
selected image's identity and explicit Client preferences, and state that the
displayed image is the basis. They exclude unverified generation descriptions.
The same image is displayed during confirmation and is retained for the Creator.
Names are labels; no image/description consistency verification is claimed.

Creator/export views of confirmed directions use the stored exact summary and
selected image, without appending the pre-render description as another agreed
requirement. Historical stored summaries are never rewritten. Old unconfirmed
records retain their readable presentation. There is no schema migration or
change to frozen Interview configuration.

Creator scope and Client preferences still govern implementation. This explicitly
resolves description drift at the agreement boundary; it does not guarantee that
image generation obeys every intended prompt detail or replace human testing.
