# 02 — Project Material to Context Pack

**What to build:** Either party can add supported Project Material, see honest processing and failure states, safely handle suspected secrets, inspect shallow source-linked File Analysis, correct it additively, and reach an immutable Context Pack Revision or explicitly continue without files.

**Blocked by:** 01 — Foundation and shared Project Room.

**Status:** ready-for-agent

## Authorized public test seams

- Project Material service operations from authorized upload through terminal analysis, retry/removal, feedback, and no-file continuation.
- Parser, secret scanner, AI analyzer, embedding, and retrieval adapter contracts at their system boundaries.
- Accessible Project Material UI using user-selected files and observable workflow states.

## Acceptance criteria

- [ ] Supported formats and configurable count/size/room limits are validated by extension, content type, and signature where available.
- [ ] Text/document parsers preserve page, slide, sheet/cell, image, paragraph, or range locators; extraction failure never injects raw content.
- [ ] Suspected text secrets are masked by default, visible safely, and may be explicitly/auditably included after disclosure.
- [ ] Durable idempotent processing records real stages and ends in `analyzed`, `unsupported`, or `failed`, with retry/remove/continue paths.
- [ ] File Analysis remains shallow, versioned, source-linked, multilingual, and correctable through additive Analysis Feedback.
- [ ] Active source chunks support room-scoped full-text and multilingual semantic retrieval without exposing raw storage URLs.
- [ ] Every material/feedback/removal change creates an immutable Context Pack Revision and retains historical availability semantics.
- [ ] English/German representative files, prompt-injection material, suspected secrets, failures, and no-file paths have focused tests.
